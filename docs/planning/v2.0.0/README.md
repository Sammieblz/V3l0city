## Completion and maintenance

Every work item includes source pages/user requirement, scope, outcome, tasks, acceptance, validation and prerequisite links. Feature PRs include meaningful tests and relevant docs; platform items maintain common harnesses/matrices, not a substitute for per-feature verification. Physical GPS, background, Bluetooth/headsets, two-car/five-vehicle/dead-zone and battery/thermal evidence remain release gates. Local functions remain available during connected failures and entitlement changes.

This uses actual GitHub issues with linked Markdown epic checklists and prerequisite references. Native Projects boards, milestone assignment, issue-type epics/sub-issue relationships and custom priority labels were not created: the available connector does not expose those mutations. The release/version/priority/scope/phase metadata is stored in issue bodies and this JSON export, using existing repository labels. A later tool/UI with those capabilities can add native metadata without recreating the issues.

Keep issue acceptance/prerequisite changes and `backlog.json` aligned. Update parent checklists as work closes; an open future checkbox does not block v2.0.0. Add evidence links and a decision record for any scope change. This planning branch changes documentation only and is intended for review into dev.
